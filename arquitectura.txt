You are a senior full-stack engineer and software architect.

I have an existing React application (already designed and implemented visually).
The UI includes login, signup, profile, pets, device dashboards and charts.
All components are already built and MUST NOT be redesigned or duplicated.

Your task is to:

1. Analyze the entire codebase and identify:
   - UI components that collect or display data
   - Forms, inputs, dashboards, charts, profile screens
   - Components that currently use mock data, local state, or placeholders

2. For each component, determine:
   - What database entity it represents
   - What fields are required
   - Whether it should be linked to a user, pet, device, or telemetry

3. Propose a relational database schema (PostgreSQL) that:
   - Uses the existing UI as the source of truth
   - Does NOT invent new features
   - Models users, pets, devices, and telemetry
   - Supports authentication via Neon Auth (users already exist in auth.users)

4. Map each UI component to:
   - A database table
   - Read / write operations (CRUD)
   - Required API or server action

5. Generate:
   - SQL table definitions
   - Minimal backend logic (queries or API handlers)
   - Frontend data bindings (fetch / mutations)
   - Without modifying component JSX structure

6. Explicit constraints:
   - DO NOT redesign UI
   - DO NOT create new components
   - DO NOT change styling
   - Only wire existing components to data
   - Reuse existing state, props, and structure

7. Output format:
   - Section 1: Component → Data Mapping
   - Section 2: SQL schema
   - Section 3: Backend glue code
   - Section 4: Frontend integration notes

Ask for clarification ONLY if something is technically ambiguous.
Otherwise, proceed with analysis.
