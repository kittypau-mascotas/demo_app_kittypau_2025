1.2 UX PILLARS (PILARES NO NEGOCIABLES)
🧠 PILAR 1 — CLARIDAD INMEDIATA (3-SECOND RULE)

Un usuario debe entender qué está pasando en menos de 3 segundos.

Aplicación práctica:

No más de 3 métricas primarias visibles por vista

Estados visuales, no texto largo

Colores semánticos universales

Estado	Color	Significado
OK	Verde suave	Todo bajo control
Atención	Amarillo cálido	Algo a vigilar
Alerta	Rojo suave	Acción recomendada

👉 Nunca rojo agresivo, KittyPau no asusta.

❤️ PILAR 2 — UX EMOCIONAL (PET-FIRST)

La mascota es un ser vivo, no un “dispositivo”.

Implicancias:

Siempre mostrar nombre y foto de la mascota

Lenguaje humano:

❌ “Temperatura fuera de rango”

✅ “La temperatura de Luna está más alta de lo normal”

Microcopy examples:

“Luna está descansando 💤”

“Todo normal por ahora”

“Podrías revisar esto cuando tengas un momento”

🧭 PILAR 3 — SISTEMA GUIADO (ZERO CONFUSION)

El usuario nunca debe preguntarse:

“¿Y ahora qué hago?”

Implementación:

Flujos obligatorios

Estados bloqueantes

CTA claros

Ejemplo:

Usuario nuevo
↓
No tiene mascota → Se muestra CTA único: “Agregar mascota”
↓
No tiene dispositivo → CTA único: “Vincular dispositivo”
↓
Sistema completo → Dashboard


👉 No dashboards vacíos
👉 No pantallas muertas

⚡ PILAR 4 — VELOCIDAD PERCIBIDA (NO SOLO REAL)

Aunque el backend tarde, la UI nunca debe sentirse lenta.

Técnicas UX:

Skeleton loaders

Animaciones suaves

Placeholder inteligentes

Cache visible

Ejemplo:

“Actualizado hace 12 segundos”

Eso genera confianza brutal.

1️⃣ FUNDAMENTOS (USUARIOS)

Neon Auth maneja neon_auth.users,
pero replicamos perfil app (best practice).

users
import { pgTable, uuid, text, timestamp } from "drizzle-orm/pg-core";

export const users = pgTable("users", {
  id: uuid("id").primaryKey(), // mismo id que neon_auth.users
  email: text("email").notNull().unique(),
  name: text("name"),
  avatarUrl: text("avatar_url"),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});
