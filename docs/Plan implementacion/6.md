6.1 PRINCIPIO FUNDAMENTAL DE ALERTAS KITTYPAU

📌 No todas las anomalías son emergencias.
📌 No todas las alertas deben interrumpir.

KittyPau sigue esta regla de oro:

Avisar lo justo, en el momento justo, con el tono justo.

6.2 TIPOS DE ALERTAS (CLASIFICACIÓN CLARA)
🟢 1. ALERTAS INFORMATIVAS

No requieren acción inmediata.

Ejemplos:

“Luna ha estado más activa hoy”

“Todo se mantiene estable desde ayer”

Canales:

In-app

Historial

🟡 2. ALERTAS DE ATENCIÓN

Requieren observación, no pánico.

Ejemplos:

“La temperatura estuvo un poco más alta esta tarde”

“La actividad bajó respecto a la semana pasada”

Canales:

In-app

Push (si el usuario lo permite)

🔴 3. ALERTAS IMPORTANTES

Requieren acción del usuario.

Ejemplos:

“La temperatura de Luna se mantiene elevada”

“No se han recibido datos del dispositivo”

Canales:

Push

Email (opcional)

In-app destacada

👉 Nunca SMS por defecto (demasiado invasivo).

6.3 TONO DE COMUNICACIÓN (CRÍTICO)
Correcto:

Calmado

Humano

Orientado a acción

Ejemplo:

“Notamos que la temperatura de Luna se ha mantenido más alta de lo habitual.
Podrías revisarla o mover su cama a un lugar más fresco.”

Incorrecto:

“ALERTA CRÍTICA”

“ANOMALÍA DETECTADA”

“ERROR DE SENSOR”

6.4 MOTOR DE ALERTAS (LÓGICA INTERNA)

Las alertas NO se basan solo en un valor puntual.

KittyPau evalúa:

Valor actual

Tendencia

Duración

Contexto horario

Historial previo

Ejemplo:

Temperatura alta + persistente + nocturna
→ Alerta de atención


👉 Esto evita falsos positivos.

6.5 UMBRALES INTELIGENTES (NO FIJOS)
Tipos de umbral:

Global (por especie)

Personalizado (por mascota)

Adaptativo (por historial)

Ejemplo:

“El rango normal de Luna se ajustó automáticamente según su comportamiento”

👉 Esto es diferenciador premium.

6.7 ALERTA = CONTEXTO + ACCIÓN

Cada alerta debe responder 3 cosas:

¿Qué pasó?

¿Es grave?

¿Qué puedo hacer?

Ejemplo:

No es urgente, pero podrías revisar su entorno.”

“Ajustar alertas”

6.8 CONFIGURACIÓN DE ALERTAS (CONTROL TOTAL)

El usuario puede:

Activar / desactivar alertas

Elegir canal (push/email)

Ajustar sensibilidad

Silenciar por horario

Ejemplo:

“No recibir alertas entre las 23:00 y 7:00”

6️⃣ DISPOSITIVOS IoT
CREATE TABLE IF NOT EXISTS devices (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  pet_id UUID REFERENCES pets(id) ON DELETE SET NULL,
  name TEXT NOT NULL,
  type TEXT NOT NULL,
  firmware_version TEXT,
  status TEXT DEFAULT 'offline',
  last_seen_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT now() NOT NULL
);

CREATE INDEX IF NOT EXISTS devices_user_idx
  ON devices(user_id);

CREATE INDEX IF NOT EXISTS devices_pet_idx
  ON devices(pet_id);

INSERT INTO devices (id, user_id, status, last_seen_at)

UPDATE devices
SET status = 'offline'
WHERE last_seen_at < now() - interval '5 minutes';
