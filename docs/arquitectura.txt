1. Contexto del proyecto

Estoy construyendo KittyPau, una plataforma IoT para mascotas.

Arquitectura actual (YA IMPLEMENTADA):

📟 Dispositivo IoT: ESP8266 / ESP32

☁️ Broker MQTT: AWS IoT Core

🖥️ Bridge: EC2 Ubuntu + Node.js (pm2)

Se suscribe a tópicos MQTT

Procesa mensajes

Guarda datos en Neon (PostgreSQL)

🗄️ Base de datos: Neon PostgreSQL

🌐 Frontend: App web (mockup, desplegada en Vercel)

La data YA VIAJA Y SE GUARDA EN NEON correctamente.

2. Identidad y relaciones (MUY IMPORTANTE)

El sistema tiene tres niveles de identidad:

👤 Usuario

Persona que usa la app

Puede tener 1 o más dispositivos

📟 Dispositivo

Identificado por un device_id (ej: KPCL0033)

Publica datos por MQTT

Está asociado a un usuario

🐾 Mascota

Pertenece a un usuario

Está asociada a un dispositivo

Tiene sensores físicos (peso, agua, ambiente)

Relaciones:

Usuario
 └── Mascota
      └── Dispositivo (KPCL0033)
           └── Sensores (peso, temp, humedad, luz)

3. Flujo real de datos (NO SIMULADO)

El dispositivo publica MQTT:

EC2 recibe el mensaje

EC2 guarda el dato en Neon con:

valores de sensores
