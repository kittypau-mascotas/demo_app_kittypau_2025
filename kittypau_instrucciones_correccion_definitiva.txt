
KITTYPAU – PLAN DE CORRECCIÓN TÉCNICA DEFINITIVO
==============================================

Este documento describe TODAS las acciones necesarias para corregir los errores detectados
por VSCode y Vercel, alineadas con la estructura definida en `definitiva.txt`.

-------------------------------------------------
FASE 0 – PRINCIPIO ARQUITECTÓNICO (NO SALTAR)
-------------------------------------------------
El proyecto es un híbrido:
- Frontend: Vite + React (client/)
- Backend: Vercel Serverless Functions (api/)
- Shared: Código compartido (shared/)
- Lib: Utilidades backend (lib/)

NUNCA se debe:
- Importar código frontend desde api/
- Usar alias Vite en backend sin paths en tsconfig
- Mezclar resoluciones browser/node

-------------------------------------------------
FASE 1 – CORREGIR tsconfig.json (CRÍTICO)
-------------------------------------------------

1.1 Archivo: tsconfig.json (RAÍZ)

PROBLEMA:
"no se encontraron entradas" + errores TS2792 en Vercel

SOLUCIÓN:
Reemplazar COMPLETAMENTE por:

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "baseUrl": ".",
    "paths": {
      "@lib/*": ["lib/*"],
      "@shared/*": ["shared/*"]
    }
  },
  "include": [
    "api/**/*",
    "lib/**/*",
    "shared/**/*"
  ]
}

IMPORTANTE:
- NO incluir client/**
- moduleResolution: NodeNext es OBLIGATORIO para Vercel

-------------------------------------------------
FASE 2 – DEPENDENCIAS BACKEND FALTANTES
-------------------------------------------------

2.1 Instalar dependencias que Vercel NO encuentra:

Ejecutar en raíz:

npm install drizzle-orm better-auth @vercel/node

2.2 Verificar que existan en package.json:

"dependencies": {
  "better-auth": "...",
  "drizzle-orm": "...",
  "@vercel/node": "..."
}

-------------------------------------------------
FASE 3 – CORREGIR IMPORTS RELATIVOS EN API
-------------------------------------------------

3.1 Archivo: api/devices.ts

CAMBIAR:
import { xxx } from "../lib/api-utils";

POR:
import { xxx } from "@lib/api-utils";

3.2 Archivo: api/auth/[...all].ts

CAMBIAR:
import { xxx } from "../../lib/api-utils";

POR:
import { xxx } from "@lib/api-utils";

3.3 Archivo: api/events.ts

CAMBIAR:
../../../lib/api-utils      → @lib/api-utils
../../../shared/db          → @shared/db
../../../shared/schema     → @shared/schema

RAZÓN:
Vercel NO resuelve rutas profundas bien sin NodeNext

-------------------------------------------------
FASE 4 – FRONTEND: ALIAS Y ARCHIVOS FALTANTES
-------------------------------------------------

4.1 Confirmar client/tsconfig.json

Debe tener:
{
  "compilerOptions": {
    "baseUrl": "src",
    "paths": {
      "@/*": ["*"],
      "@shared/*": ["../../shared/*"]
    }
  }
}

4.2 Crear archivos UI faltantes (OBLIGATORIO)

Crear:
client/src/components/ui/button.tsx
client/src/components/ui/skeleton.tsx
client/src/components/ui/tooltip.tsx
client/src/components/ui/toaster.tsx

Stubs mínimos válidos.

4.3 Crear context faltante

Crear:
client/src/contexts/AuthContext.tsx

Debe exportar:
- AuthProvider
- useAuth()

Aunque sea mock.

-------------------------------------------------
FASE 5 – Devices.tsx (ERRORES TS)
-------------------------------------------------

5.1 Error:
parameter 'device' implicitly has 'any'

SOLUCIÓN:
Crear interfaz:

interface Device {
  id: string;
  name: string;
}

Y usar:
(device: Device)

5.2 Hook faltante

Crear:
client/src/hooks/data/useDevices.ts

Exportar:
export function useDevices() {
  return { data: [], isLoading: false };
}

-------------------------------------------------
FASE 6 – import.meta.env ERROR
-------------------------------------------------

Archivo:
client/src/vite-env.d.ts

Debe existir con:

/// <reference types="vite/client" />

SIN ESTO:
import.meta.env falla en TS
